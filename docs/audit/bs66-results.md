## What 0.2.29 adds that the book has no page for

The contract's items 2 and 3 presume a page that teaches signals. There
is none: no page, sample or exercise names an `os_signal_*` builtin,
`os_pid`, `os_ppid`, `os_proc_pid` or `std.signal` (grep over `book/`,
`principles/`, `samples*`; the sweep's 580 programs reach none). So no
page was brought up to date and no sample was added; these are listed
instead.

1. **Signals as a subject** (`[os.signal]`): a program registers
   interest and receives a signal as an event, with no handler. The
   book's index, glossary and Part 4 have no entry. Everything below
   needs that page first.
2. **The signal set at 0.2.29** (`[os.signal.set]`): twenty listenable
   meanings (the nine of 0.2.28 and `USER`, `ALARM`, `BROKEN_PIPE`,
   `ABORT`, `CONTINUE`, `RESIZE`, `URGENT`, `VIRTUAL_ALARM`,
   `PROFILE_ALARM`, `CPU_LIMIT`, `FILE_LIMIT`), eight send-only (`KILL`,
   `STOP`, the six faults), and the one shape rule (an empty set or a
   bit that is not listenable is `io`).
3. **A published bit is permanent** (`[os.signal.set.stable]`): a
   meaning keeps its bit forever; a program names a meaning, never a
   host number, and `os_signal_number` is the one way to a host number.
   A page will have to say how a reader spells a meaning at this
   release: the prelude has no constant, and the bundled `std.signal`
   names nine of the twenty. That is a ruling to ask for before the page
   is written (print the bit from the spec's table for the eleven, or
   wait for a release whose std names them); no page may print a host
   number.
4. **`os_pid` and `os_ppid`** (`[os.proc.self]`).
5. **`os_signal_send`** (`[os.signal.send]`; `exec`), **`os_signal_number`**
   (`[os.signal.number]`; no capability), **`os_signal_ignored`**
   (`[os.signal.ignored]`; `env`). A page that shows them shows lupin
   refusing `os_signal_send` and `os_signal_ignored` by name (the table
   above) and, on windows, `unsupported` for all but `os_pid`
   (`[os.signal.platform]`; not measured here).
6. **Which builtin charges which capability** (ruling #70 R8): ch24
   §24.3 teaches the seven capabilities and E1504 and has no table of
   builtins; nothing there is made false.
7. **A worker per parked task** (s231): no cap on parked tasks, about
   15 KiB each on linux x86-64, the host's thread limit the last word.
   No page described the old cap. ch10's "What a task costs" says what
   the runtime does about a pool with blocked members is unobservable
   and not to be depended on, and ch12's "The million idle connections"
   is a claim about `select`; both stand, and neither is the page for a
   task-per-connection server.
8. **`wolf lsp` finds std; `wolf lsp --std-root`** (s235): appendix E
   names `lsp` among the five subcommands with no chapter behind them.
9. **The bundled std's new wrappers** (wolf-std `d7c2968`: `fs.set_mode`,
   `create_private`, `create_with_mode`, `create_dir_mode`, `symlink`,
   `link`, `fs.Time`, `set_times`, `set_link_times`, `truncate`,
   `env.umask`): the book prints no std sample (§25.2 held,
   wolf-book#45).
