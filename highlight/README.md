# highlight/ — the single-source highlight contract

The `*.tmLanguage.json` files here are **vendored, not authored**:
generated by wolf-lsp's `cargo xtask grammar-generate` from the pinned
spec EBNF (spec → EBNF → tmLanguage → book, one lineage) and copied
from wolf-lsp `clients/vscode/syntaxes/` at the rev pinned in
`wolf-toolchain.toml` (`[wolf-lsp].rev`). Do not edit them here — the
remedy for a change is a pin bump plus `cargo xtask grammar-sync`, one
commit.

`cargo xtask grammar-sync` re-copies from a wolf-lsp checkout and
regenerates `wolf-highlight.css` (which is `theme/highlight.css`, the
one CSS file every output format shares); `--check` mode fails on any
byte drift between this directory and the checkout at the pin — the
same discipline wolf-lsp applies to its own arrow with `grammar-drift`.

Rendering happens at build time in the xtask preprocessor: a minimal
TextMate-grammar interpreter (`xtask/src/tm.rs`) consumes these JSON
grammars directly and emits classed spans; no highlight.js, no
client-side JS, no second wolf grammar. (Delta from DESIGN.md §2's
naming of syntect: syntect parses `.sublime-syntax`, not tmLanguage
JSON, so consuming the vendored grammar *directly* meant a small
in-house interpreter. The contract's substance — one grammar, build
time, one CSS — is unchanged; recorded for the campaign closeout.)
